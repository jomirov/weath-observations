## Цель

Создание локального API для введения записей о погоде двух пользователей.

- Таблица Observations (id, owner_id, city, temperature_C, note)
- Реализация методов запроса POST, GET, GET by id, DELETE by id
- Фиксированные уникальные токены для каждого пользователя (определение owner_id по токену)
- Возврат ошибок при неверных данных (отсутствие токена, обращение к чужой записи)
- Автоматизированное тестирование

## План
1. Создание окружения
1. Установка и настройка FastAPI, SQLite3
1. Создание таблицы observations (id, owner_id, city, temperature_C, note)
1. Создание объекта для работы с БД и реализация CR~~U~~D
1. Реализация методов запроса POST, GET, GET id, DELETE id
1. Конфигурация запросов:
    - запрос заголовка "X-TOKEN" и прочих параметров
    - обработка исключений
    - создание дополнительных зависимостей (валидация, сверка токена)
1. Заполнение и сохранение данных на базе
1. Четыре тестовых сценария:

    |  Проверка   | Ожидаемый результат |
    | -----------    | ------ |
    | Создание записи Пользователем А | Код статуса - 201; Запись принадлежит Пользователю А |
    | Отправка запроса с невалидными данными | Код статуса - 422; Запись не был сохранен в базе |
    | Попытка запроса с невалидным токеном | Код статуса - 401 |
    | Доступ к данным чужого пользователя | Код статуса - 404; В списке записей Пользователя А не содержатся записи Пользователя В |
1. CI Github
